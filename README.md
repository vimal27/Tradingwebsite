# Ledger — Personal Trading Journal

An offline-first trading journal tailored to `Investments_V2.xlsx`. It opens as a local web page—no server, build step, database, login, cloud sync, or network connection is required.

## Run it

Keep `index.html` and `ledger-seed.js` together, then open `index.html` in a modern browser. The first open seeds the browser's local storage with the workbook history. Later changes are stored locally and do not change the original Excel workbook.

The starter data contains 31 detailed records from **Option chain V3** and 67 from **Commodities V3**. **Consolidated V2** is a daily rollup of P&L rather than another set of trades, so Ledger displays its daily chart separately instead of adding it to the detail rows.

The imported detail records total **-₹11,771.12**; Consolidated V2 reports **-₹8,063.19**. The difference is surfaced in the app for review. The detail sheets cover different date ranges, and the consolidated sheet also includes legacy option references, so the two totals should not be treated as interchangeable.

## Use the journal

- **Overview:** cumulative and monthly P&L, win/loss distribution, performance by market, and a separate daily chart from Consolidated V2. Date filters include 7/30/90 days, each of the current and prior two calendar months (for example, October, September, August), and **All time**.
- **Trade history:** search, filter by date range or sprint, edit, or delete entries. Sprint filtering uses the sprint's start/end dates, so it also includes older trades without a PBI link. Recorded P&L is preserved as-is when editing imported trades.
- **Monthly reports:** calculate Options, Commodities, and Consolidated results from the current trade history, grouped by date and month. A positive daily net P&L counts as a target/profit day, a negative result as a loss day, and a zero result on a trade date as a no-P&L day. Total trading days shows all eligible weekdays in the month, excluding NSE holidays; elapsed trading days and no-trade days count only dates through today, so future sessions are not mislabeled as no-trade. Accuracy is profitable days divided by days with non-zero P&L. Consolidated V3 adds Options and Commodities results by date. Its Donation amount column accepts a manual amount for each month and saves it locally. Current-month P&L and outcomes are month-to-date.
- **Trade review:** data-derived comparisons, including market and instrument results, average wins/losses, largest win/loss, longest losing streak, process-discipline tags, notes mentioning chase entries, planned Options risk/reward coverage, and the workbook rollup difference. These are descriptive observations, not financial advice.
- **Add trade:** enter completed trades directly. New entries calculate net P&L from entry, exit, quantity, contract units per lot, side, and fees unless you provide a P&L override. Defaults include NIFTY/NFY options at 65, SENSEX/SNX options at 100, NatGasMini/NaturalGas at 250, and CrudeOil mini at 10; the multiplier field is visible and editable for each instrument. Record the optional **Max profit before SL** amount to compare the best unrealized profit reached with the final result; this value is available in the trade history and preserved when editing or importing. You can optionally link a trade to a sprint PBI and record whether you followed your plan and risk controls, chased an entry, overtraded, or were distracted/unsafe.
- **Sprint board:** one-week, named sprints start with two editable PBIs: NIFTY/SENSEX and Commodities. Set each title, description, and target; when a market has one PBI its actual uses the market's sprint trades for backward compatibility. If multiple PBIs share a market, actuals use only trades explicitly linked to that PBI, preventing the same trades being counted toward every goal. Completing a sprint marks each PBI as achieved/within its loss limit or **Failed** when its target is missed. The sprint review reports trade counts, wins, losses, win rate, P&L, discipline tags, and unassigned trades by market, and can be exported as CSV. Starting another sprint completes the active one after confirmation.
- **Daily Scrum:** record what went well, what went wrong, and the next-day focus for each market. The day's trade count and P&L are calculated from the trade log; you can also note whether you followed the sprint's improvement points. Filter Scrum entries by date range.
- **Scrum Master discussion:** start a guided two-part reflection that asks about NIFTY/SENSEX first and Commodities second, then summarizes process strengths, potential rule breaches, and a next-session focus. The on-device coach personalizes prompts from recent trades, strategy labels, process tags, and notes, and saves its conversation locally as part of the JSON backup. View past discussions or delete an individual discussion from the open chat or its history. To preserve the no-server/offline design, this is a transparent rule-based coach—not a cloud language model, live-market feed, or substitute for your own risk controls. It only flags phrases and journal evidence for review; it cannot verify what happened in the market.
- **Sprint retrospective:** save worked-well, went-wrong, and improvement notes for each sprint. Filter dated retrospectives by sprint start date; imported retrospective notes without reliable dates remain visible when no date filter is applied. The PlanningLocal workbook's historical planning, Scrum notes, sprint reviews, and retrospectives are included as local reference history.

Some source fields are not recorded consistently. Options quantity and commodity position side are left blank/unknown rather than guessed. The workbook's cached P&L values are retained for those records, including rows that lack entry/exit details.

## Data and backups

The bundled `ledger-seed.js` and `sprint-seed.js` are local starter snapshots of the workbook trade and planning history. When deployed with the included Cloudflare Pages Function and `LEDGER_DATA` R2 binding, the journal loads from and saves to `/api/data` across devices. Cloudflare Access should protect the Pages site/API so only your account can write. If the cloud API is unavailable, the app continues using this browser's local storage and shows a notice.

Use **Data & settings → Download JSON backup** regularly. The page shows the approximate serialized journal size and last local download date, and recommends a backup if one has not been downloaded or it is older than 30 days. The full JSON backup includes trades, PBI links, discipline tags, sprints, Scrum notes, retrospective/planning history, donations, and locally added NSE holidays. The built-in NSE holiday dates cover 2026; add further or future official closure dates under **Data & settings → NSE trading holidays** to keep eligible-day and no-trade-day counts accurate. Importing a full backup replaces current local journal and sprint data after confirmation; older trade-only JSON files and CSV imports continue to append trades. CSV import recognizes the workbook's Option headings (`Premium`, `Entry`, `Exit`, `SL`, `Tgt`, `Brokerage`, `P/L`, `Comment`) and Commodities headings (`Instrument`, `Strategy`, `Lots`, `Buy`, `Sell`, `Brokerage`, `P/L`), including Excel-serial dates. CSV imports append rows and do not deduplicate; avoid re-importing the preloaded rows or importing Consolidated V2 as trades.

## Cloudflare Pages + R2 setup

1. Create an R2 bucket named `tradingwebsite-data`.
2. Connect this repository to Cloudflare Pages.
3. Configure the `LEDGER_DATA` R2 binding for the Pages project using the binding name in `wrangler.toml`.
4. Deploy the site and protect the Pages project with a Cloudflare Access application. The Pages Function at `/api/data` uses the R2 object `ledger.json`.
5. Open the site while signed in through Access. The first successful save creates or updates the R2 JSON document.
